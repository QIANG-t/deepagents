# 只读解释评测 v1：8 案例 × 3 次

日期：2026-09-28。本报告评当前已实现的**单 Build 事实快照与 DeepSeek 只读解释**。评测集为[8 个匿名合成案例](fixtures/readonly_explanation_eval_v1.json)，覆盖共享库存、库存充足、消耗与分配、两个 Part、库存注释冲突、注释缺失、空需求行及超额分配归零。原 [18 案采购流程方案](evaluation_plan.md)涉及报价、审批和建单，口径不同，未计入本轮成绩。

运行方式和判定边界见[只读评测说明](../evals/README.readonly.md)。合成数据由真实 `build_facts` 函数生成预览，再由独立的 `Decimal` 计算与手写期望值交叉核对。DeepSeek 通过插件同一 `generate_explanation` 函数，实际调用 `deepseek-flash` 和绑定该合成快照的 `read_task_snapshot`；这一步不经过 InvenTree HTTP、数据库或浏览器。真实插件链路另见[第三阶段联调](milestone3_deepseek_integration_validation.md)。

| 指标 | 固定模板（无模型） | DeepSeek |

“技术契约”对 DeepSeek 指模型名、完整快照摘要、非空有界文本、恰好一条 `read_task_snapshot` 成功调用、调用 ID 和与工具快照匹配的 SHA-256；模板只检查自身标识、摘要与非空文本，**两组的契约不同，不能拿此行比较解释质量**。DeepSeek 的契约验证模型实际通过工具取得输入，但不证明整段自然语言都正确。“文字覆盖提示”只查 Build 引用、行 ID、Part IPN、完整摘要以及来源/未核实字样；它不能确认数字与字段配对正确，空行案例的 ID 提示还会因没有 ID 而自然成立，因此不称作事实准确率。全部解释仍需人工复核。

固定输入 SHA-256：`3c2c8316627c86fa3ff2491eaed8f630ea89994893a18d1dfc9248330e86d585`。DeepSeek 运行时解释源码 SHA-256：`95d117e21d2b2e9bd198aedff92faa77d26e0d266ac2c98c59c73cbf102216e8`。24 条合成响应与逐次耗时保存在本机 `/tmp/readonly-eval-results/deepseek-v1.json`，不提交到 Git；模板结果在 `/tmp/readonly-template-eval-v1.json`。两份报告不含 API Key。评测代码复核后，原始 DeepSeek 响应被离线重新评分，未发起新 API 请求；对比用报告为 `/tmp/readonly-eval-results/deepseek-v1-rescored.json`。可提交的[基线汇总](../evals/baselines/readonly_deepseek_v1_summary.json)只保留逐案例计数、评分代码哈希和输入哈希；下次改动后可用 `compare` 命令检查是否有单个案例退步。评测脚本的 7 个新增单元测试及原有 11 个离线评测测试均通过。

## 判断与下一步

在**仅解释结构化快照**的任务上，固定模板已覆盖所有机器提示，而 DeepSeek 多了一次摘要缩写和调用耗时。当前数据不能证明模型比模板更适合此步骤。建议保留 DeepSeek 路径用于展示受控工具调用，同时把“完整摘要在正文中保留”设为下一轮回归目标；真正比较 Agent 的增益，应等报价原文、冲突证据和澄清任务接入后，和相同输入的规则模板比较。真实并发、更多 InvenTree Build、费用和语义盲评仍待做。
