# 第六阶段：只读采购决策预览

真实匿名报价样本暂缺，本阶段不扩大报价评测。已有插件分别展示生产单缺口和报价证据；本阶段把它们合并成逐物料的**人工核对清单**，不创建可审批方案或采购单。

## 已实现

`GET /plugin/inventree_procurement/tasks/<task_id>/decision-preview/` 从任务保存的生产单快照和报价生成确定性结果。每个 Part 一行，显示初步缺口、该 Part 关联的 SupplierPart、报价单价/币种/计价单位，以及固定的待核实原因。接口和页面都将 `order_quantity`、`estimated_total` 固定为空，状态为 `needs_review`。没有模型调用、审批动作或采购单写入。

清单明确提醒：需求和库存是已保存的快照；初步缺口没有扣除在途供应，也未处理替代料、可选及消耗性物料；订货单位换算、订货倍数、价格档位、计价单位和报价有效性还未完成业务核实。无法核实缺口、初步缺口为零、物料不可采购、缺少报价或报价与当前 SupplierPart 冲突时，也会逐项显示。**初步缺口不是建议下单数量。**

每个任务目前只保存一份报价。新报价保存提取时的 Part ID 和生产单快照摘要；读取决策预览时重新检查当前用户权限、SupplierPart 与任务 Part 的关联，并重新计算冲突。旧报价缺少原始关联信息、快照摘要不一致，或 SupplierPart 后来改绑时，预览只提示“报价关联待核实”，不会把报价挂到另一个物料上；用户需要新建任务并重新提交报价。页面提供刷新按钮以读取最新结果。

## 隔离实例验证

在 `inventree-spike` 实例中，测试生产单 `BO-9001` 两条同物料需求分别为 4 和 6，可用库存 5 只计一次，初步缺口为 **5**。关联一份合成的 USD 12.50/pack 报价后，真实 URL 返回一行关联报价；可下单数量和估算总价仍为空。匿名请求返回 401，其他用户的任务返回 404；调用前后 PurchaseOrder 和 PurchaseOrderLineItem 数量相同。复现脚本为[决策预览验证](../plugin/integration/verify_decision_preview.py)，报价输入由[报价验证](../plugin/integration/verify_quote.py)创建。前端 8 项契约测试、构建，以及后端 50 项单元测试通过；没有新增数据库迁移。

当前验证覆盖接口和前端构建，尚未再次手动走一遍浏览器页面。要把清单推进为可下单草稿，需要先确认实时库存与在途、替代料政策、单位换算、订货倍数、价格档位和报价有效性，并设置人工核准及幂等写入的测试门槛。

## 面试讲法

“我没有把模型抽出的 USD 12.50 直接乘以缺口 5。缺口是物料原生单位，价格是每包，且库存快照未扣在途、包装换算和报价档位都未核实。程序只生成一张可审计的核对清单，明确缺什么信息，数量和总价保持空值。模型负责抽取原文，是否能采购由确定性规则和人工确认决定。”
