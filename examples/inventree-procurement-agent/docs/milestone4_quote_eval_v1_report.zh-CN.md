# 第四阶段：粘贴报价的真实联调与回归

用户选择了“**手工粘贴匿名纯文本，关联已有 SupplierPart**”。本阶段在隔离的 InvenTree 实例中完成了只读报价提取：用户提交一份最多 8 KiB 的文本，DeepSeek 通过一次任务绑定的 `read_quote_snapshot` 工具读取原文与供应商物料事实，服务端核对原文证据并保存一个不可覆盖的结果。这里的“只读”指**不创建或修改采购单**；提交报价会在插件自己的任务表中保存原文和提取结果。

## 实例联调

隔离实例使用 `BO-9001`、`SPIKE-COMP-001` 和 SupplierPart `SPIKE-QUOTE-001`。测试账户是非超级用户，具备 Build、物料、库存及供应商价格的查看权限。合成报价中的单价为 USD 12.50/pack；结构化价格阶梯是 USD 10.00，但两者的订购档位与计价单位没有完成同语义证明，因此页面显示“价格阶梯对照：待核实”，没有误报价格冲突。

真实 HTTP 测试确认：匿名 GET 返回 401，其他用户的任务返回 404，缺 CSRF 的 POST 返回 403，首次有效 POST 返回 201，同源重复提交返回缓存 200，改动原文返回 409。结果包含原文 SHA-256、八个字段的精确原文位置、检查状态，以及一次真实 `read_quote_snapshot` 工具调用的 ID 和结果 SHA-256。测试前后的 PurchaseOrder 与 PurchaseOrderLineItem 数量相同。隔离浏览器也完成了登录、进入 Purchasing 插件面板、粘贴报价、提交并查看证据与工具调用的流程；临时测试登录随后被禁用。测试脚本见 [报价 HTTP 验证](../plugin/integration/verify_quote.py)和[隔离种子数据](../plugin/integration/seed_quote_fixture.py)。

首次真实调用暴露了模型给错字符下标的问题。服务端现在仅在证据片段于原文中**唯一出现**时重算下标；重复片段且下标不明确时拒绝结果。后续评测还发现：多档报价可能被误选第一档、MOQ 可能被误当包装量、`TBD` 可能被误当确定交期。服务端分别做了保守过滤，并保持供应商、SKU、金额等字段的原文证据校验。任何失败均不生成采购单。

离线判分器只能验证提交的 JSON，不能独立证明它来自真实模型调用。真实调用的复现入口是[隔离运行脚本](../plugin/integration/run_quote_eval.py)，判分方法与限制见[评测说明](../evals/README.quote.md)。它还不能判断一个复杂文档里引用的片段是否属于正确的商品或报价条件；七条合成文本只是第一批回归样本。

## 面试可说明的取舍

“我先做一个能真实运行的最小链路：InvenTree 生产单预览 → 用户粘贴匿名报价 → DeepSeek 只读工具抽取 → 服务端核对原文证据。评测发现模型会误选阶梯价、混淆 MOQ 与包装量，还会把 `TBD` 当交期，因此这些字段由程序保守过滤。七个合成案例各跑三次，当前版本通过 18/21；失败返回错误而不会生成采购单。下一步需要扩大真实匿名样本并验证单位、价格档位语义，才适合讨论自动采购。”
