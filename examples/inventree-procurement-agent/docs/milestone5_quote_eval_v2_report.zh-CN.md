# 第五阶段：扩大报价评测与失败归因

这轮保留 [v1 的 7 条合成报价](fixtures/quote_eval_v1.json)及其历史哈希，新增 [v2 的 15 条合成报价](fixtures/quote_eval_v2.json)：Q01–Q07 原样复制，Q08–Q15 补充重复证据、中文阶梯价、MOQ 与包装量并存、供应商冲突、未知交期、提示注入和无单位的包装量。**这些都不是用户真实报价**。

## 真实调用结果

在隔离的 `inventree-spike` 实例上，每条样例连续运行 3 次 `deepseek-flash`，再用同一版[离线判分器](../evals/quote_offline.py)重评保存的 API 结果。判分器只看提交的结果，不能单独证明模型调用；真实调用由[受限运行脚本](../plugin/integration/run_quote_eval.py)完成。

| 运行 | 案例 × 轮次 | 判分通过 | 服务端拒绝 | 单次耗时中位数 |
| --- | ---: | ---: | ---: | ---: |
| v1 复测，加入安全失败分类后 | 7 × 3 | 21/21 | 0 | 1.87 秒 |
| v2 首轮，包装量对照修复前 | 15 × 3 | 39/45 | 3 | 1.85 秒 |
| v2 修复后 | 15 × 3 | **44/45** | **1** | 1.87 秒 |

原始合成结果分别保存在 [v1 复测](../evals/baselines/quote_deepseek_v5_observations.json)、[v2 首轮](../evals/baselines/quote_deepseek_v2set_observations.json)和 [v2 修复后](../evals/baselines/quote_deepseek_v2set_fixed_observations.json)。v2 首轮的 39/45 是用最终判分器重评的结果；修复前后不是同一组模型输出，因此分数差不能全归因于代码修改。v1 原报告的 v4 成绩仍是 18/21，三次旧失败没有诊断元数据，原因未知。

v2 首轮的三次服务端拒绝已归类为：Q06 `evidence_metadata_invalid`、Q05 `invalid_json`、Q09 `numeric_unsupported`。修复后仅 Q05 有一次 `evidence_metadata_invalid`。运行记录只保存固定的失败阶段和代码，不保存失败时的模型原始响应或 provider 异常文本；因此我们仍不能知道那一次的具体错误字段。拒绝结果不保存报价，也不触发采购单写入。

## 本轮改动与边界

- 对明确的 `Pack quantity: 8` 这类整行包装量，程序现在读取原文标签，确认数值无单位、所选 SupplierPart 的单位明确为空且有原生包装数量，才比较 `match` 或 `conflict`。MOQ、价格行、多个数字和带单位的包装量仍保持 `unverified`。这修复了 Q15 原先 3 次被判为未核实的问题。
- v2 判分器在首次基线固定前加入窄等价：`元/包` 与 `包` 表示同一个计价单位；任意前缀和错误原文位置仍不通过。Q10 原先两次因此被判错。v1 案例和预期答案没有修改。
- 保持严格拒绝无效 JSON、证据元数据和无原文支持的数字。当前 44/45 是合成文本的小样本结果，不是准确率承诺；还需要真实匿名报价及更复杂的多商品文件。

固定输入 SHA-256：v1 `508d50b7fdc64e710c4daa6d3462887df68564febd0e322e8b02eeaf3be2d450`；v2 `ada018389db3a765d5b2f1844085d289e899583601c3a9127c0901e389467674`。44/45 真实运行时的 `quote.py` SHA-256 为 `5e33b75aee55319648d1dab7754f2f5137710a132818994221cb2bca6109ffe0`。随后将包装量比较进一步收紧为**无单位数字**，最终文件 SHA-256 为 `98b38f8c6c9309a48d806bcd272ec94598b176797dbd0f1a3916640984a6b119`；该调整经过单元测试和 HTTP 联调，但未再次执行 45 次模型调用。最终判分器 SHA-256：`677f5a715bf64a73ace3e69c60e0deab880554de01404c45479ddcf24d9c263d`。

面试时可以说明：我们先冻结旧测试集，再加难例；真实重复调用暴露了一个确定性业务比较错误和少量模型格式错误。确定性错误通过读取原文标签修复；模型格式错误继续由服务端拒绝并记录固定失败类别。下一步要收集真实匿名报价，人工标注证据和错误类型，再决定是否需要重试或结构化输出约束。
